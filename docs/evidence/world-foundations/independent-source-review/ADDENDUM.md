**No concrete duplicate-owner, consent, or return-checkpoint defect found in this change.** `CosmosUI.tick` first preserves `in-cosmos`, hides the old home button when adopted, and clears old labels before its early return. `WorldUI.local` (`src/world-foundations-ui.js:11`) takes ownership for a Roads-entered Cosmos trip or an explicitly active Cosmos work run. A quiet legacy visit with no active work therefore retains its original presentation without accepting work. `RPGUI.tick` calls Cosmos before WorldUI (`src/rpg-ui.js:313`), so the shared owner subsequently writes its tracker/home/labels and the old owner cannot overwrite those fields later in the same tick. The shared page and interaction handlers also precede the legacy handlers (`src/rpg-ui.js:77,147-150,162`).

An adopted legacy trip still has no `worldTrip`, so the exact app `worldReturn` delegates to `cosmosReturn` (`src/app.js:12,20`). `RealmCosmos.leave` uses the original `returnPos` and clears the transient trip (`src/cosmos.js:87-89`, `src/core.js:92`). Roads-entered trips instead use the shared return path. Neither UI tick grants work consent or changes saved state.

Executed six bounded Node/VM cases using actual production Cosmos/WorldUI tick functions with a small fake DOM, production old/new travel functions, the exact two app return function bodies, and the labelled initial-kit fixture. All passed: (1) unaccepted legacy visit has the old home and 1 old label, 0 shared labels; (2) explicit legacy opening acceptance has shared home and 3 shared labels, 0 old labels; (3) a paid legacy run with no remaining active work returns to one old owner; (4) explicit legacy repeat acceptance adopts the shared owner again; (5) the adopted legacy return restores the original observatory-side checkpoint and retains the accepted record, with both home buttons hidden afterward; (6) Roads entry owns presentation before any work consent, with 3 shared labels and no old labels.

The ownership condition deliberately lasts only while an old-entry work run is active; claiming that run restores the legacy presentation when there is no Roads trip. That behavior follows the unchanged `WorldUI.local` contract and was explicitly checked, rather than assuming takeover persists for the entire legacy visit.
